Hospitality Revenue Dashboard

Standardizing hotel performance before visualizing it

  • SQL

GitHub ↗

Business value

Management gained self-service cross-property performance visibility from one consistent KPI layer.

01 · Business problem

More than 10 properties used disconnected spreadsheets and inconsistent KPI definitions, making cross-location comparisons unreliable.

02 · My approach

I began with stakeholder requirements and KPI definitions, then designed the analytical model before the dashboard.

03 · What I built

A star-schema SQL model, standardized property data, Power BI dashboards, and DAX measures for RevPAR, DBRN, occupancy, and revenue.

What changed my thinking

The corrections, tradeoffsand decisions behind it.

  1. 01

    The KPI dictionary came first

    A polished dashboard would still be wrong if each property defined performance differently.

  2. 02

    The semantic layer created trust

    Standard definitions made cross-location comparison possible.

  3. 03

    Self-service changed the value

    The dashboard reduced dependence on disconnected manual reports.
